    Limites e fontes de verdade¶

    • Em produção: o comportamento deve ser confirmado nas rotas e no deploy; o guia de hospedagem distingue configuração de publicação efetiva.
    • Banco: o SQL em migrations mostra o esquema versionado. As políticas aplicadas no projeto Supabase precisam ser verificadas no ambiente; uma migração no Git não comprova sua execução.
    • RLS e autorização: a auditoria é um registro histórico, enquanto cibersegurança acompanha mudanças em andamento. Não confundir a análise de 02/11 com o estado posterior.
    • Comentários e moderação: documentos e desenhos são propostas, não telas funcionais. As regras dependem de aprovação e implementação específica.
    • Histórico: Release 1, Release 2 e implementações antigas registram entregas passadas; não devem substituir as instruções atuais.

    Manutenção e validação¶

    1. Alterou uma rota, tabela, tela ou workflow? Atualize sua página de referência e revise os documentos relacionados na tabela.
    2. Prefira links relativos para páginas internas; preserve nomes de arquivos, URLs permanentes e identificadores usados pelo código.
    3. Rode python -m unittest discover -s tests -t . para mudanças de código.
    4. Rode mkdocs build --strict para a documentação e verifique links internos, títulos e navegação antes do PR.
    5. Use o Definition of Ready e Definition of Done.
